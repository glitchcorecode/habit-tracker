## БЛОК 1. АНАЛИЗ ТРЕБОВАНИЙ И КЛАССИФИКАЦИЯ ПО

### 1.1. Классификация и лицензирование ПО (Кейс CampusPlanner)
Был проведен анализ лицензионной чистоты проекта. Выявлен конфликт: библиотека PlannerCore (GPLv3) напрямую связана с проприетарным клиентом. 
Были предложены три модели распространения, выбрана самая безопасная: замена GPL-компонента на библиотеку с разрешительной лицензией (MIT/Apache) для сохранения закрытости исходного кода клиента.

### 1.2. Разбор инцидента и RACI-матрица (Кейс Release Lab)
Проведен разбор инцидента с релизом. Составлена матрица ответственности RACI (Кто выполняет, кто отвечает). 
Разобраны шаги пайплайна: автоматические ворота (G1-G5), пилотный запуск, оценка качества и безопасный возврат версии (Rollback) с сохранением данных.

### 1.3. Уровни тестирования сервиса бронирования
Спроектированы проверки для сервиса бронирования аудиторий на 4 уровнях:
- Unit: проверка отдельных функций (валидация размера, проверка пересечений).
- Integration: проверка обработчика и записи в БД.
- System: проверка действий через экран и сохранения.
- Acceptance: проверка бизнес-сценария (бронирование аудитории).
Составлены 12 тест-кейсов и проведен регрессионный анализ.

## БЛОК 3. ТЕСТИРОВАНИЕ ПРОИЗВОДИТЕЛЬНОСТИ (КЕЙС КИНОАРХИВ)

### 3.1. Нагрузочное тестирование «Кадр за кадром»
Смоделирована работа киноархива (тяжелые задачи реставрации по 1600 мс и легкие превью по 200 мс). Проведено 12 экспериментов.
Выявлено, что при потоке «Фестиваль» (8 задач/с) 3 вычислительных слота не справляются.
Определено, что увеличение очереди не решает проблему нехватки мощности, а приоритет коротких задач (SJF) спасает превью, но вызывает голодание тяжелых реставраций (TIMEOUT).
Выбрана оптимальная конфигурация: 5 слотов, очередь 40, FIFO.

## БЛОК 4. РАЗРАБОТКА ВЕБ-ПРИЛОЖЕНИЯ (ИТОГОВЫЙ ПРОЕКТ)

### 4.1. Описание проекта Habit Tracker
Веб-приложение «Трекер привычек» на HTML, CSS и чистом JavaScript (Vanilla JS). 
Функционал: добавление, удаление, редактирование привычек, живой поиск, прогресс-бар, автоматическая архивация выполненных задач при смене дня. Данные сохраняются в localStorage. Интерфейс выполнен в темной стилистике (Web Tactics) с использованием CSS Grid.

### 4.2. Ветвление и первая функция (Практикум 2)
Создана ветка `feature/first-feature`. Добавлена возможность редактировать привычку по двойному клику (через `prompt()`). Добавлена защита от пустого ввода. Ветка слита в `main`.

### 4.3. Вторая функция, рефакторинг и конфликт Git (Практикум 4)
- Новая функция: добавлено поле поиска для фильтрации привычек в реальном времени.
- Рефакторинг: перегруженная функция `updateUI` разбита на части, создание DOM-элемента вынесено в `createHabitElement`.
- Учебный конфликт: в ветках `fix/text-1` и `fix/text-2` по-разному изменен подзаголовок сайта. Вызван конфликт слияния (CONFLICT), который был разрешен вручную объединением текста.

### 4.4. Автотесты и Git Revert (Практикум 5)
- Логика фильтрации вынесена в `logic.js`.
- Написаны 3 теста в `logic.test.js` с использованием модуля `node:test`.
- Тест выявил дефект: поиск не работал, если ввести запрос с пробелами по краям (например, " спорт "). 
- Дефект исправлен добавлением `.trim()`. Все 3 теста проходят.
- Отработана безопасная отмена изменений через `git revert` (создан и отменен учебный коммит `chore`).
